第一章 设计模式概述

设计模式是软件开发中常见问题的经典解决方案。它们是经过实践检验的最佳实践，可以帮助开发者编写更加优雅、可维护的代码。

1.1 什么是设计模式

设计模式是一套被反复使用、多数人知晓的、经过分类编目的代码设计经验的总结。

1.2 设计模式的分类

设计模式主要分为三大类：

1. 创建型模式：处理对象创建机制
2. 结构型模式：处理类和对象的组合
3. 行为型模式：处理对象之间的通信

第二章 创建型模式

2.1 单例模式

确保一个类只有一个实例，并提供一个全局访问点。

示例：

class Singleton {
  private static instance: Singleton;
  
  private constructor() {}
  
  public static getInstance(): Singleton {
    if (!Singleton.instance) {
      Singleton.instance = new Singleton();
    }
    return Singleton.instance;
  }
}

2.2 工厂方法模式

定义一个创建对象的接口，让子类决定实例化哪一个类。

2.3 抽象工厂模式

提供一个创建一系列相关或相互依赖对象的接口。

2.4 建造者模式

将一个复杂对象的构建与它的表示分离。

2.5 原型模式

通过复制现有对象来创建新对象。

第三章 结构型模式

3.1 适配器模式

将一个类的接口转换成客户希望的另一个接口。

3.2 装饰器模式

动态地给一个对象添加一些额外的职责。

3.3 代理模式

为其他对象提供一种代理以控制对这个对象的访问。

3.4 外观模式

为子系统中的一组接口提供一个一致的界面。

3.5 组合模式

将对象组合成树形结构以表示"部分-整体"的层次结构。

3.6 桥接模式

将抽象部分与它的实现部分分离。

3.7 享元模式

运用共享技术有效地支持大量细粒度的对象。

第四章 行为型模式

4.1 观察者模式

定义对象间的一种一对多的依赖关系。

4.2 策略模式

定义一系列算法，把它们一个个封装起来。

4.3 命令模式

将一个请求封装为一个对象。

4.4 模板方法模式

定义一个操作的算法骨架，将一些步骤延迟到子类中。

4.5 迭代器模式

提供一种方法顺序访问一个聚合对象中的各个元素。

4.6 责任链模式

使多个对象都有机会处理请求。

4.7 状态模式

允许一个对象在其内部状态改变时改变它的行为。

4.8 备忘录模式

在不破坏封装性的前提下，捕获一个对象的内部状态。

4.9 中介者模式

用一个中介对象来封装一系列的对象交互。

4.10 解释器模式

给定一个语言，定义它的文法的一种表示。

4.11 访问者模式

表示一个作用于某对象结构中的各元素的操作。
